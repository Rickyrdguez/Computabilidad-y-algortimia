=========================================
APUNTES: std::map y std::multimap (C++ STL)
=========================================

--------------------------
1. QUE SON
--------------------------
Contenedores asociativos ORDENADOS de la STL. Guardan pares clave-valor
(std::pair<const Clave, Valor>), ordenados automaticamente segun la clave
(por defecto con operator<).

- std::map        -> claves UNICAS (una clave = un unico valor)
- std::multimap    -> claves REPETIDAS (una clave puede tener varios valores)

Complejidad de busqueda/insercion/borrado: O(log n) en ambos (arbol
binario equilibrado por debajo).


--------------------------
2. DECLARACION
--------------------------
#include <map>

std::map<std::string, double> notas_;
std::multimap<std::string, double> notas_;

- No hace falta constructor propio: al crearse, ya nacen vacios
  (el compilador genera un constructor por defecto implicito que
  llama al constructor por defecto de map/multimap).


--------------------------
3. INSERTAR ELEMENTOS
--------------------------

map:
  mapa[clave] = valor;
    -> si la clave NO existe: la crea y le asigna el valor.
    -> si la clave YA existe: SOBRESCRIBE el valor anterior.
  mapa.insert({clave, valor});
    -> si la clave ya existe, NO la sobrescribe (no hace nada).

multimap:
  NO tiene operator[] (no tendria sentido: una clave puede tener
  varios valores, no se sabria cual devolver).
  multimapa.insert({clave, valor});
    -> SIEMPRE anhade una entrada nueva, aunque la clave ya exista.
    -> Las entradas con la misma clave quedan agrupadas y
       consecutivas (por el orden interno del arbol).


--------------------------
4. BUSCAR / COMPROBAR EXISTENCIA
--------------------------

find(clave)
  -> Devuelve un iterador a la primera entrada con esa clave,
     o mapa.end() si no existe.
  -> Sirve para map y multimap.
  auto it = mapa.find(clave);
  if (it != mapa.end()) { ... existe ... }

at(clave)
  -> Solo en map. Devuelve el valor asociado (referencia), pero
     LANZA una excepcion si la clave no existe. No crea nada.
  -> No confundir con operator[] (que SI crea si no existe).

count(clave)
  -> Devuelve cuantas entradas hay con esa clave (0 si no existe,
     1 en map, puede ser >1 en multimap).

equal_range(clave)   [MUY UTIL EN MULTIMAP]
  -> Devuelve un std::pair de DOS iteradores:
       .first  -> primera entrada con esa clave
       .second -> primera entrada YA NO de esa clave (limite superior)
  -> Sirve para recorrer solo las entradas de una clave concreta,
     y tambien para "saltar" de golpe al siguiente grupo de clave
     distinta en un bucle exterior.

  auto rango = multimapa.equal_range(clave);
  for (auto it = rango.first; it != rango.second; ++it) {
    // it->first  = clave (siempre la misma en este bucle)
    // it->second = uno de los valores de esa clave
  }


--------------------------
5. ITERADORES
--------------------------
Tipo completo:  std::map<K,V>::iterator / const_iterator
Con auto:       auto it = mapa.find(clave);

- it->first   -> la clave (es const, no se puede modificar)
- it->second  -> el valor (SI se puede modificar directamente,
                 no es una copia; ej: it->second = 9.5;)

- En un metodo marcado "const", begin()/end()/find() devuelven
  const_iterator (no dejan modificar el valor). Por eso usar
  "auto" evita tener que pensar en si toca iterator o const_iterator.


--------------------------
6. RECORRER TODO EL CONTENEDOR
--------------------------
for (const auto& elemento : mapa) {
  // elemento.first  -> clave (con punto, NO flecha, porque
  //                    "elemento" es una referencia, no un iterador)
  // elemento.second -> valor
}

- Recorrer un map o multimap entero siempre da los elementos
  ORDENADOS por clave (ascendente por defecto).


--------------------------
7. OTRAS FUNCIONES UTILES
--------------------------
mapa.size()       -> numero de elementos
mapa.empty()      -> true si esta vacio
mapa.erase(clave) -> borra TODAS las entradas con esa clave
                     (en multimap borra todas las repetidas)
mapa.erase(it)    -> borra solo la entrada a la que apunta el iterador
mapa.clear()      -> vacia el contenedor entero


--------------------------
8. RESUMEN: CUANDO USAR CADA UNO
--------------------------
map:
  - Necesitas una unica clave -> un unico valor (ej: alu -> nota maxima).
  - Quieres operator[] para leer/crear comodo.

multimap:
  - Necesitas que una misma clave tenga varios valores asociados
    (ej: alu -> todas sus notas).
  - Vas a usar equal_range() para agrupar/mostrar por clave.
  - Alternativa a valorar: map<Clave, vector<Valor>> suele ser mas
    eficiente en insercion (push_back es O(1) amortizado frente a
    O(log n) de insert en multimap) y tiene mejor localidad de
    memoria, pero exige gestionar tu el vector interno.


--------------------------
9. ERRORES TIPICOS A EVITAR
--------------------------
- Usar operator[] en multimap: NO EXISTE, no compila.
- Comparar const_iterator con iterator sin que coincidan los tipos
  (usar auto lo evita).
- Hacer un for sobre it->second en multimap pensando que es una
  coleccion: en multimap, it->second es UN SOLO valor (double, etc.),
  no una lista. Para varios valores de una clave, usar equal_range().
- Reutilizar el mismo iterador para el bucle exterior y el bucle
  interior (de equal_range) a la vez: usar variables distintas.
- Rango.second NO es "el siguiente valor de la misma clave": es el
  iterador limite, que apunta a la primera entrada de la SIGUIENTE
  clave distinta (o a end() si era la ultima clave).
